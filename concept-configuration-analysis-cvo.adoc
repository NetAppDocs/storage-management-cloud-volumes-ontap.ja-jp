= AzureのCloud Volumes ONTAPシステムの構成分析
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
Workload Factoryは、NetApp Consoleからストレージシステムの構成を定期的に分析し、Azure上のCloud Volumes ONTAPシステムに構成上の問題がないかどうかを判断します。問題が検出されると、Well-Architectedダッシュボードに問題の内容と、ストレージシステムが最高のパフォーマンス、コスト効率、およびベストプラクティスへの準拠を達成するために必要な変更に関する推奨事項が表示されます。

主な機能は次のとおりです：

* 日次構成分析
* NetApp ONTAPストレージシステムおよびパートナーストレージプロバイダーに対する自動ベストプラクティス検証
* プロアクティブな可観測性
* 洞察から行動へ


link:https://docs.netapp.com/us-en/workload-family/index.html["Workload Factoryの詳細をご覧ください。"^]



[[how-it-works]]
== 仕組み

Workload Factoryは、サポートされているクラウドストレージシステム上で実行されているワークロードを毎日分析します。この分析により、適切に設計されたステータス、インサイト、および推奨事項が提供されます。

日々の分析が完了すると、デプロイメントのWell-architectedダッシュボードに、構成が「最適化済み」または「最適化されていない」として表示されます。設定に関する問題はカテゴリ別に整理されており、設定に関する問題とその推奨事項の一覧も掲載されています。設定に関する問題については、推奨事項をご確認ください。Workload Factoryは一部の問題を自動的に修正できますが、その他の問題には手動での対応が必要です。この場合、Workload Factoryは、推奨される変更を実装するための詳細な手順を提供します。

ご自身の環境に適用されない構成の分析を無視することができます。これにより、不要なアラートや不正確な最適化結果を回避できます。

また、組織の標準とNetAppのベストプラクティスに照らして環境を検証するために、平易な言葉でカスタムルールを作成することもできます。ドライランでルールをテストし、各環境で実行するようにスケジュールを設定します。



[[why-it-matters]]
== 重要な理由

Workload Factory は、継続的な評価と推奨事項、および修復策を組み合わせることで、大規模なストレージ、データベース、および VMware 環境にベストプラクティスを適用します。自動化された修正機能は、人的ミスを減らし、均一な管理を確保し、ワークロードインフラストラクチャ全体でパフォーマンスと信頼性を維持します。



[[analysis-requirements]]
== 分析要件

Cloud Volumes ONTAP に関連付けられたコンソールエージェントが、以下のエンドポイントにアクセスできることを確認してください。

* \https://api.workloads.netapp.com
* \https://ws.workloads.bluexp.netapp.com




[[best-practices-and-recommendations-for-cloud-volumes-ontap-systems]]
== Cloud Volumes ONTAP システムのベストプラクティスと推奨事項

Workload Factoryはストレージ構成を評価し、ONTAP構成のベストプラクティスやAzure Well-Architected Frameworkへの準拠に関する詳細なビューを提供します。この評価では、改善点や修正点も推奨します。

適切に設計された分析では、構成をフレームワークの次の柱に分類します：_信頼性_、_セキュリティ_、_運用効率_、_コスト最適化_、および_パフォーマンス効率_。



[[reliability]]
=== 信頼性

信頼性とは、障害発生時であっても、ワークロードが意図された機能を正確かつ一貫して実行することを保証するものです。

* *Snapshotポリシー*
+
効率的なバックアップと迅速なリストアのために、ローカルSnapshotをスケジュール設定してください。Snapshotは、ボリュームのポイントインタイムイメージを瞬時に作成します。

* *SSDキャパシティのヘッドルーム*
+
アプリケーションの読み取り / 書き込みやスループットに影響が及ぶのを防ぐため、SSDストレージ階層の使用率は80%未満に維持してください。容量は手動または自動で増やすことができます。

* リモートデータレプリケーション
+
リモートレプリケーションによってCloud Volumes ONTAPのデータを保護します。リモートデータレプリケーションは、データの同期コピーを異なる場所に保持することで、災害復旧機能を提供し、システム障害や災害が発生した場合でも事業継続性を確保します。





[[security]]
=== セキュリティ

セキュリティは、リスク評価と軽減戦略を通じて、データ、システム、資産を保護することを重視します。

* *AIによる自律型ランサムウェア対策（ARP/AI）*
+
NetApp Autonomous Ransomware Protection with AI（ARP/AI）は、サイバーレジリエンスを強化し、ランサムウェアの脅威からボリュームを保護します。すべてのボリュームでARP/AIを有効にすることをお勧めします。





[[operational-excellence]]
=== 運用の卓越性

運用上の卓越性とは、最高のアーキテクチャとビジネス価値を提供することに重点を置くものです。

* *ボリューム容量のヘッドルーム*
+
アプリケーションの読み取り / 書き込みやスループットに影響が及ぶのを防ぐため、ボリュームの使用率は80%未満に維持してください。容量は手動で、またはボリュームの自動拡張を使用して増やすことができます。

* *FlexCache 書き込みモード*
+
最適なパフォーマンスを得るには、ワークロードに最適なFlexCache書き込みモードを選択してください。ライトアラウンドモードは、小さなファイルを扱う読み込み中心のワークロードにおいて優れたパフォーマンスを発揮し、ライトバックモードは、大きなファイルを扱う書き込み中心のワークロードにおいて優れたパフォーマンスを発揮します。

* *FlexCacheレプリカサイズ*
+
キャッシュボリュームの自動サイズ変更とスクラビングを有効にして、最適なサイズを維持し、頻繁にアクセスされる（ホット）データにキャッシュを集中させることで、最高の効率を実現します。

* *ONTAPバージョン準拠*
+
完全な互換性、サポート、および新機能へのアクセスを実現するには、最新バージョンの ONTAP にアップグレードしてください。





[[cost-optimization]]
=== コスト最適化

コストの最適化により、コストを低く抑えながらビジネスの価値を最大限に高めることができます。

* *SSD容量のオーバープロビジョニング*
+
過剰なSSD容量は、不必要なコスト増につながります。SSDの容量を減らしつつ、20%の空き容量バッファを維持します。この操作には数時間から数日かかる場合があり、その間は他のファイルシステム操作はサポートされません。

* *コールドデータ階層化*
+
コールドデータ階層化を有効にして、コールドデータをSSDストレージ階層から低コストのストレージに移動します。すべてのボリュームに階層化ポリシーを適用します。
