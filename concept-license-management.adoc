= Cloud Volumes ONTAP の BYOL ライセンスについて
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Bring-Your-Own License（BYOL）は、クラウド マーケットプレイスのサブスクリプションを使用する代わりに、NetApp から直接ライセンスを購入する Cloud Volumes ONTAP の課金モデルです。

BYOLは、標準モードおよびプライベートモードの展開で利用可能ですが、利用制限があります。BYOLライセンスは、NetApp Consoleの「*ライセンスとサブスクリプション*」セクションの「*直接ライセンス*」で管理できます。各ライセンスは、お客様の会社および特定のNetApp Support Siteの認証情報に関連付けられています。

* NetApp は、有効なマーケットプレイスサブスクリプションを持つ標準モード展開における BYOL ライセンスの購入、延長、および更新を制限しました。詳細については、 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/whats-new.html#restricted-availability-of-byol-licensing-for-cloud-volumes-ontap["Cloud Volumes ONTAPの BYOL ライセンスの利用制限"^]を参照してください。
* NetAppはノードベースのライセンスを段階的に廃止し、容量ベースのライセンスに移行しています。ノードベースのライセンスは、一部のUSPS顧客向け導入事例や中国における導入事例など、限られた既存の導入事例に対して引き続き利用可能です。詳細については、 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html#end-of-availability-of-node-based-licenses["ノードベースライセンスの提供終了"^]を参照してください。




[[byol-deployment-modes]]
== BYOL展開モード

[role="tabbed-block"]
====
.標準モード展開
--
* BYOLの代わりに、NetAppは年間または従量課金制（PAYGO）マーケットプレイスのサブスクリプションによる消費量の課金を推奨しています。
* 標準モードの導入では、一般的にノードベースのライセンスではなく、容量ベースのライセンスが使用されます。既存の標準モード展開のうち、ノードベースのライセンスを使用しているものはごく少数です。


--
.プライベートモードでの展開
--
* プライベートモードでの展開は、マーケットプレイスのサブスクリプションがプライベートモードでは利用できないため、BYOL ライセンスに完全に依存します。
* 新規導入の場合は、ノードベースのライセンスではなく、容量ベースのEssentialsパッケージを使用してください。ノードベースのライセンスは、一部の古いプライベートモードのデプロイメントで使用されています。


--
====


[[compare-byol-license-types-in-private-mode]]
=== BYOLライセンスの種類をプライベートモードで比較する

以下の表は、プライベートモードにおける容量ベースライセンスとノードベースライセンスの違いをまとめたものです。

[cols="25,37,38"]
|===
| 機能 | 容量ベースのライセンス | ノードベースのライセンス 


| 導入サポート  a| 
新しいプライベートモードの展開では、容量ベースのライセンス（具体的には Essentials パッケージ）のみがサポートされます。
 a| 
新規のプライベートモード展開では、ノードベースのライセンスはサポートされていません。既存のノードベースの展開のうち、引き続き使用できるのは限られた数のみです。



| 購入  a| 
容量ベースの BYOL Essentials パッケージを NetApp から購入し、デプロイ時にシステムに割り当ててください。
 a| 
ノードベースのライセンスで既存のプライベートモード展開がある場合は、NetApp から Essentials パッケージを購入することで容量ベースのライセンスに変換できます。



| Capacity  a| 
最初の500 GiBの消費容量は、ライセンス料金の対象外です。ワークロードの要件が増大するにつれて、追加のパッケージを購入することができます。
 a| 
ノードベースのライセンスでは、単一ノードまたは HA ペアに対して最大 368 TiB の容量が提供されます。Cloud Volumes ONTAP システムに 368 TiB 以上を割り当てるには、複数のライセンスを購入してください。例えば、ライセンス 2 つで最大 736 TiB、ライセンス 4 つで最大 1.4 PiB の容量が提供されます。



| Scope  a| 
容量ベースのライセンスは、Cloud Volumes ONTAP システム全体で共有される容量プールから利用されます。ストレージのニーズの変化に応じて、利用可能な容量を再配分できます。
 a| 
各ノードベースのライセンスは、1つの Cloud Volumes ONTAP システムに適用され、そのシステムに一定量の容量を提供します。



| 移転可能性  a| 
容量ベースのライセンスはそれぞれ、Console アカウントに関連付けられています。そのアカウントで作成されたシステムは、ライセンス容量とシリアル番号を共有できます。例えば、5 TiB のライセンスは、それぞれ 2.5 TiB のシステム 2 台、または 5 TiB のシステム 1 台をサポートできます。Console でライセンスのシリアル番号を確認でき、同じアカウントで複数のシステムに同じライセンスを割り当てることができます。
 a| 
ノードベースのBYOLライセンスは、既存のシステムを削除し、そのライセンスを使用して新しいシステムを作成することで移行できます。クラウド プロバイダに依存しないシリアル番号のみが、複数のクラウド プロバイダ間で機能します。これらのシリアル番号は_908xxxx_という接頭辞で始まります。

|===


[[manage-and-renew-byol-licenses]]
== BYOLライセンスの管理と更新



[[renew-a-byol-license]]
=== BYOLライセンスを更新する

BYOLライセンスを更新するには、NetAppの担当者にお問い合わせください。コンソールは、更新されたライセンスを自動的に取得して Cloud Volumes ONTAP システムにインストールします。

コンソールが安全なインターネット接続経由でライセンスファイルにアクセスできない場合は、ライセンスファイルをダウンロードしてlink:task-manage-node-licenses.html["コンソールに手動でアップロードする"]。

Console に関連付けられた NetApp Support Site の認証情報を管理するには、 https://docs.netapp.com/us-en/console-setup-admin/task-adding-nss-accounts.html["NetApp Console に関連付けられた NSS 認証情報の管理"^]を参照してください。



[[respond-to-an-expiration-warning]]
=== 有効期限切れ警告に対応する

コンソールには、ノードベースのライセンスの有効期限が切れる30日前と、ライセンスの有効期限が切れた際に警告が表示されます。Cloud Volumes ONTAP システムを選択して、警告内容を確認し、ライセンスを更新してください。

image:screenshot_warning.gif["スクリーンショット: 警告アイコンを含むCloud Volumes ONTAPシステムを示しています。アイコンはアクションが必要であることを示します。"]

組織管理者またはアカウント管理者で、このオプションを有効にしている場合、コンソールには Cloud Volumes ONTAP レポートにライセンスの有効期限切れ警告が含まれ、お客様にメールで送信されます。

ライセンスの有効期限が切れる前に更新しない場合、Cloud Volumes ONTAP システムがシャットダウンします。ライセンスを更新せずにシステムを再起動すると、再びシャットダウンします。
